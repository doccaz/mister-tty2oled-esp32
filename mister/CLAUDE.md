# mister/ notes (moved from the root CLAUDE.md)

### MiSTer-side WiFi daemon (`mister/`, 2026-10-17)

**Runs next to the stock tty2oled daemon, never replaces it (owner's decision).** It lives in `/media/fat/t2o-wifi/` (binary, `t2o-wifi.ini`, `S60t2o-wifi`, `art/`), reads the stock folder only for its ini files and `pics/`, pid `/run/t2o-wifi.pid`, log `/tmp/t2o-wifi.log`. No name, path or argv contains `tty2oled`, because the stock `S60tty2oled stop` runs `ps | grep tty2oled | awk 'NR==1{print $1}'` and could pick (and kill) our process; reading the script, not reproduced on a MiSTer. The menu's boot toggle only edits our own line in `user-startup.sh`.

Go, standard library only (own RFC 6455 client in `wslink.go`), cross-compiled static for
`GOARCH=arm GOARM=7` by `mister/build.sh`; ~2.7 MB. It watches `/tmp/CORENAME` with inotify (the
directory, not the file, because the file is sometimes replaced), looks up art (`art/*.jpg`, then
the stock pics folders with the stock name-shortening and `_alt` rules) and sends `CMDCORC` over
ws://host:81 in 2 KB chunks. Legacy `.gsc/.xbm` are converted to a 240x240 JPEG by the daemon
(`legacy.go`, same 240x60 nearest-neighbour layout as the firmware's `drawLegacyScaled()`),
because the firmware refuses legacy pictures over WebSocket; a gray JPEG still gets tinted by the
device. JPEGs are capped at 19,000 bytes (device buffer 20,000). `CMDCON/CMDROT/CMDSAVER` are NOT
sent by default (`WIFI_SEND_SETTINGS`), because they would override the device's settings page
until its next reboot. `HOST` can be a `.local` name: the MiSTer can't resolve those, so `mdns.go` is a stdlib mDNS resolver. The ESP32's responder ignores queries from an ephemeral source port (tried first, 0 answers on the real device); it only answers when the query comes from port 5353 (found with a Python probe), so it binds 5353 per interface via `ListenMulticastUDP` and reads the multicast answer. Verified against the real display from a PC, and on a real MiSTer (2026-10-17, listed and resolved both displays).
Several displays (2026-10-17): `HOST` takes up to 3 comma-separated displays (`maxDisplays`, small on purpose for the MiSTer). One `daemon` per display (`run()`), one shared `ArtFinder` with a 5 s `FindShared` cache so the art is looked up/converted once and the `_alt` dice is the same for all; one inotify watcher fans out to a buffered channel per display; uploads staggered 0.4 s. Settings are per display through name-prefixed ini keys (`CD20_CONTRAST`; `hostKey()` = host without `tty2oled-`/`.local`, upper case; `Config.forHost`). The menu picker multi-selects (Enter/Space toggles, then "Save selection") and Options has a "Settings for" scope line. Tested with fakes and two real displays on the MiSTer (live: both got NES/SNES). Further confirmed on the install MiSTer (2026-10-21), which ran **two wireless displays plus one wired display on the stock tty2oled** at the same time — the three co-exist cleanly, which is the whole point of running beside the stock daemon rather than replacing it.
Menu: `t2o-wifi -menu` (`tui.go`, `tui_term.go`; plain ANSI over a raw-mode termios, no library) edits only `t2o-wifi.ini` and our own `user-startup.sh` line (the stock daemon's line is never touched; an earlier version commented it out). A first version used `dialog` (what the MiSTer scripts normally use) and was replaced because it looks dated and needs sed/grep for state. Console unknowns: the MiSTer console font may not have box-drawing glyphs, so ASCII lines are the default unless `LANG`/`LC_ALL` says UTF-8; tested in tmux, then on a real MiSTer over SSH (2026-10-17: looks fine, both displays selectable and driven). One read can carry several keys (tmux send-keys, key repeat), so the parser loops over the buffer.
Auto-update (2026-10-21, verified on a real MiSTer): the daemon is distributed as a MiSTer Downloader custom database so `update_all`/`update` keep it current. `tools/build_mister_db.py` emits a plain `t2o-wifi-db.json` (schema `v:1`, `db_id doccaz_mister_tty2oled_gc9a01`, lowercase/underscores so it also works as a `downloader.ini` section and a drop-in `downloader_<id>.ini` name) describing four files relative to `/media/fat`: `t2o-wifi/t2o-wifi` (`reboot:true`), `t2o-wifi/S60t2o-wifi`, `Scripts/t2o_wifi.sh`, and `t2o-wifi/t2o-wifi.ini` with `overwrite:false` so a user's `HOST`/settings are never clobbered. Per-file `url` points at the matching GitHub release asset (plain asset names `t2o-wifi`, `S60t2o-wifi`, ... - they don't collide with the firmware `*.bin`); `base_files_url` is not usable because release assets are a flat list that can't carry the folder paths. The db is published at a **stable** Pages URL (`.../t2o-wifi-db.json`) whose contents change each release but whose URL never does. `release.sh` builds the daemon (pinning `VERSION=$TAG` so the binary's MD5 matches what gets served) and uploads the four assets; `build_site.sh` regenerates and publishes the db from those assets (and **fails loudly in CI if any daemon asset is missing**, since a Pages deploy replaces the whole site and a skipped db would 404 for every subscriber - `pages.yml` downloads the daemon assets, not just `*.bin`). `--dry-run` rehearses the daemon build + db generation.

Manual update: `t2o-wifi -update` and the menu's "Check for updates" read that **same** published db (so they can never disagree with `update_all` about what's current). The db URL is a compiled default (`updateDBURL`) that `DB_URL` in `t2o-wifi.ini` overrides (`dbURL()`, 2026-10-21) - so a future repo/Pages rename, which moves the Pages URL and would otherwise dead-end the baked-in URL until an `update_all` reinstalls the daemon, can be fixed with one ini line instead. "Is there an update?" is `local-exe MD5 != db MD5` (works for dev builds too, no version-string compare). It verifies the download's size+MD5 **before** swapping - a truncated binary renamed into place would brick both the daemon and the menu (the menu is how users recover). exFAT-safe swap order: download to `.new`, verify, stop the daemon, rename, restart; the menu re-execs the new binary on exit (`tui.go`'s `reexec`) rather than keep paging the replaced file off exFAT. `update.go`'s `fetchURL` shells out to `wget` (then `curl`), the tools the stock tty2oled scripts use and the MiSTer is known to have - deliberately **not** Go's `net/http`+`crypto/tls`, which nearly doubled the always-running binary (2.7→6.3MB) for a feature used a few times a year and whose TLS path can't be tested off-device; the MiSTer CA bundle is `/etc/ssl/certs/cacert.pem` (from the stock scripts' wget invocations). **Verified end-to-end on a real MiSTer (2026-10-21, v0.5.4)**: a live `update_all` installed the daemon (binary updated from the older build, `S60t2o-wifi`/`t2o_wifi.sh` already current, errors none), and the downloader listed `t2o-wifi/t2o-wifi.ini` under "new versions were not installed" - `overwrite:false` kept the user's customized `HOST` untouched. Right after, `-update` read the same db and reported up to date (both paths agree). The `-update` swap itself was then exercised by installing a stand-in binary (different MD5, version `v0.5.4-swaptest`) and running `-update`: it downloaded, verified size+MD5, stopped the running daemon, renamed over the exFAT binary, restarted the daemon (new pid), left no `.new` file, and a second `-update` reported up to date. `update_test.go` also covers the db parse/compare and `fetchURL` against an `httptest` server. Note the full `update_all` run reboots the MiSTer when it also updates cores (and our binary carries `reboot:true`).

Service discovery: the firmware (from 0.5.3) advertises `_tty2oled._tcp` (port 81, TXT `ver`, `hw`) next to `_http`/`_ws` (`enterConnected()`), and `t2o-wifi -list/-select`, `HOST="auto"` browse it (PTR query; SRV/TXT/A from the answer). Older firmware is found through `_ws._tcp` + the `tty2oled-` name prefix, which is how it was tested live on two real displays; the new service is flashed and seen by avahi-browse on CD20 (ver, hw TXT). A reader goroutine left running after a browse stole the next query's answers (found live: the fallback browse got nothing) - readers are now stopped and waited for. Verified with a fake WebSocket display and unit tests, and end to end on 2026-10-17: a real MiSTer (stock tty2oled running beside it) sent MENU/NES/SNES/Genesis art from the mono pack to two real displays, all drawn correctly. Also confirmed on the MiSTer: the menu's d-pad keys, and start at boot (the init script waits for a default route first; before that the daemon sat ~30 s in mDNS back-off). A display with no version in its mDNS record gets it from `GET /status` (`fillVersions`).

### Art lookup order, the public-domain pack, and the test picker (2026-10-23)

`mister/art.go`'s `findFile` checks, at each name length of the prefix-shortening loop: `art/` (the
user's own pictures), then the stock `pics_pri` (exact name only), then `art-pd/` (the downloaded
pack), and only after all lengths the stock `pics/` folders. So a user file always wins at the same
length, a longer pack match still beats a shorter user match, and a core with no colour art falls back
to the stock grayscale. `ArtFinder.Names()` lists every name with a picture (art, art-pd, stock; no
extensions or `_altN`, de-duplicated, sorted); `TestFinderPackOrder` pins the order.

**Pack distribution (built, nothing published yet).** `tools/release_art.sh` re-checks the Commons
licences (`tools/check_commons_licenses.py`, report `tools/PD_LICENSE_CHECK.md`), builds the
public-domain-only set (`tools/build_pd_set.py` into the gitignored `library/pd-set/`: only themes
whose source is a Commons file tagged public domain, rendered with the pack masters and loaders
removed, and verified pixel-identical to `color-gen`), stages `art-pd_<core>.jpg` +
`art-pd_ATTRIBUTIONS.md` + `art-pd_MANIFEST.json`, and publishes them as release `art-pd-N`.
`build_art_db.py` generates a SECOND Downloader database, `t2o-wifi-art-db.json` (`db_id`
`doccaz_mister_tty2oled_art_pd`, opt-in via `downloader.ini`), installing into
`/media/fat/t2o-wifi/art-pd/`, never `art/`: the Downloader overwrites same-named files, so it must
not touch the user's own art. Hashes/sizes come from the uploaded asset bytes (a fresh render could
differ), and the manifest is the completeness check (a missing picture exits non-zero). Traps handled:
the art release is created `--latest=false` because `pages.yml` and `gh release view` treat the latest
release as the firmware one (a pack release in that slot would break the next deploy and the flasher);
`pages.yml` downloads the newest `art-pd-N` and `build_site.sh` regenerates the art database on EVERY
deploy (a deploy replaces the whole site; with no pack release it just isn't published). The new
folder does nothing until a daemon release that knows `art-pd/` is cut with `tools/release.sh`.
Verified only by `--dry-run`, the failure cases and `go test`: no release was cut, no database
published, and the new daemon was not installed on a MiSTer.

**Menu test picker.** A joystick has no text entry, so "Send a test picture" opens a small menu:
current core (from `/tmp/CORENAME`), random core, pick from a list (Up/Down move, Left/Right jump to the
previous/next initial letter; the stock folder alone is ~1,900 names), or type a name (SSH/keyboard).
The result notice names the random pick and now survives the 1.5 s status refresh (it used to be wiped by
the refresh tick). Tested in tmux with arrow keys only and a real send to a display.

**On-screen keyboard and per-display settings (2026-10-24).** `tui.go`'s `input()` now shows a key grid (letters, digits, `- _ .`, Shift/Space/Del/Clear/OK) that a d-pad drives; the cursor rests on OK so Enter from a real keyboard still saves, and typing resets it there. Every text field uses it. The new main-menu "Display settings" (`tui_settings.go`) picks one display of HOST, reads its `GET /status` (firmware, ip, rssi, uptime, heap) and sends live `CMDCON`/`CMDROT`/`CMDCLS` to just that display. Those last until the display restarts; the display does not report its brightness, so the value shown is the last one sent (starting from the ini). Saved defaults still live on the display's own `/settings` page. Still text-only for
joystick users: "Type an address by hand" in the display picker (the found-displays list works without
it); Options' contrast already has Left/Right steps.
